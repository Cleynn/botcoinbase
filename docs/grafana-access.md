# Grafana access

Grafana (`https://grafana.tradingdots.onthewall.ovh`) is for **diagnostics only**. The daily operations UI is the main dashboard, which only links to Grafana and never embeds it. Grafana has no bot controls, and its dashboards are read-only.

## Signing in
- Own login required. Anonymous access, self-registration, organisation creation, sharing (public dashboards, external snapshots), plugin installation, update checks, alerting and Grafana's own `/metrics` are disabled.
- Administrator user: `td-admin`. Password: `GRAFANA_ADMIN_PASSWORD` from `.env` (never committed, generated by `scripts/bootstrap.sh`). `GRAFANA_SECRET_KEY` is a second, separate secret (Grafana's built-in default key is publicly known, so a unique one is required).
- Production validation (`make verify-security-config`, `scripts/verify_monitoring_config.py --env-file .env`) fails if either secret is missing, shorter than 32 characters, a placeholder (`CHANGE_ME…`) or a known default (`admin`, `SW2YcwTIb9zpOOhoPsMm`, …). Compose refuses to start Grafana without them (`${VAR:?}`, no default).
- Cookies are `Secure` and `SameSite=Strict`; Grafana's brute-force login protection stays on. Signing in to the main dashboard and to Grafana are independent (different accounts, cookies and hostnames).

## Rotating the admin password
Change `GRAFANA_ADMIN_PASSWORD` in `.env`, then reset it inside the container (Grafana stores the password on first start, so the environment variable alone does not change an existing account):
```
docker compose exec grafana grafana cli admin reset-admin-password "$(grep ^GRAFANA_ADMIN_PASSWORD= .env | cut -d= -f2-)"
```
Rotating `GRAFANA_SECRET_KEY` invalidates stored datasource secrets and sessions (there are none of value: the provisioned datasource has no credentials).

## Dashboards
Provisioned from `infra/monitoring/grafana/`: cannot be edited or deleted in the UI (`allowUiUpdates: false`, `disableDeletion: true`, `editable: false`). To change one, edit the file in the repository and redeploy; Grafana reloads provisioned files within about a minute. The datasource (`Prometheus`, uid `prometheus`, `http://prometheus:9090` over the internal network) is also provisioned and read-only.

## Optional second layer (recommended if the hostname is guessable)
Not enabled by default. If a stable source address exists, restrict the Grafana host in `infra/caddy/Caddyfile`:
```
@blocked not remote_ip 203.0.113.0/24   # replace with your address range
handle @blocked { respond 404 }
```
(or use Caddy `basicauth` with a hash kept outside the repository). Re-run `scripts/verify_monitoring_config.py` afterwards; do not proxy any other target.

## Not verified here
